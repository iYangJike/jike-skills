# Supabase  一站式后端服务

- [Supabase 官方地址](https://supabase.com/)

**介绍**

> 开源 BaaS（Backend-as-a-Service）平台，用 PostgreSQL 做核心，提供数据库、认证、存储、自动 API、实时推送、边缘函数。对标 Firebase，但 完全开源、SQL 强、可自托管、无锁定。
> 
> 
**核心优势**
1. 数据库（Database）
托管 PostgreSQL，可视化建表、SQL 编辑器
支持：表、视图、存储过程、触发器、外键、索引
自动 REST API：GET/POST/PATCH/DELETE 对应表 CRUD
2. 认证（Auth）
邮箱 / 密码、魔法链接（无密码）、短信验证码
OAuth：Google、GitHub、Facebook、微信、Apple 等
JWT 管理、用户元数据、会话控制
RLS 行级安全：auth.uid() 绑定用户与数据权限
3. 存储（Storage）
文件上传 / 下载 / 删除、私有 / 公开桶
图片优化（resize、format）、CDN 加速
权限控制：按用户 / 角色控制文件访问
4. 实时（Realtime）
订阅 INSERT/UPDATE/DELETE 变更
广播消息、 presence 在线状态
前端直接接收推送，不用轮询
5. 边缘函数（Edge Functions）
全球部署 TypeScript 函数
处理支付、webhook、敏感逻辑
低延迟、免运维、按调用计费

## supabase  auth 登录接入

supabase 默认会将 email 登录的验证方式打开，可在 email 相关选项卡中，配置 email的邮件模板。

！！ 注意：如果使用 email的登录方式，在上线之前 一定要打开  STMP setting 的设置。

**STMP 相关配置（以 QQ邮箱为例）**

Host: smtp.qq.com
Port: 465（SSL）或 587（STARTTLS）
User: QQ 邮箱
Pass: 授权码（非登录密码）

**QQ邮箱 开通 STMP 方法参考**

1. 登录网页版 QQ邮箱 
2. 点击设置
3. 点击 ’账号与安全‘
4. 点进 安全设置后，下拉页面找到  POP3/IMAP/SMTP/Exchange/CardDAV 服务 ，根据提示操作即可。

## supabase 后端开发（数据库）

** SQL 数据表生成 prompt **
> 如果不知道应该创建 哪些数据表，及相关配置，可让 ai 基于现有功能进行对应数据库的创建。
> 提示词如下：
> 
```
#file:page.tsx  我准备给我这个todolist应用添加 supabase 的后端数据库，请你根据现有的功能，给我一个表的创建语句，并且同时包含对应的 RLS policy 语句，用户只有登录之后才能添加
```
1. 在项目根目录，创建一个 sql/init.sql 的文件夹，将生成内容复制到文件夹中。
2. 回到 supabase 中，在 sql Editor 中，将生成的内容，复制到其中。

**生成内容如下**
```
-- ============================================
-- 1. 创建 todos 表
-- ============================================
CREATE TABLE IF NOT EXISTS public.todos (
  id BIGSERIAL PRIMARY KEY,
  text TEXT NOT NULL,
  completed BOOLEAN NOT NULL DEFAULT false,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  image_url TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================
-- 2. 创建索引以提升查询性能
-- ============================================
-- 为 user_id 创建索引，加速用户的 todos 查询
CREATE INDEX IF NOT EXISTS idx_todos_user_id ON public.todos(user_id);

-- 为 created_at 创建索引，加速排序查询
CREATE INDEX IF NOT EXISTS idx_todos_created_at ON public.todos(created_at DESC);

-- 复合索引：用户ID + 创建时间，进一步优化常见查询
CREATE INDEX IF NOT EXISTS idx_todos_user_created ON public.todos(user_id, created_at DESC);

-- ============================================
-- 3. 创建自动更新 updated_at 的触发器
-- ============================================
CREATE OR REPLACE FUNCTION public.handle_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_updated_at
  BEFORE UPDATE ON public.todos
  FOR EACH ROW
  EXECUTE FUNCTION public.handle_updated_at();

-- ============================================
-- 4. 启用 Row Level Security (RLS)
-- ============================================
ALTER TABLE public.todos ENABLE ROW LEVEL SECURITY;

-- ============================================
-- 5. 创建 RLS 策略
-- ============================================

-- 策略1：用户只能查看自己的 todos
CREATE POLICY "Users can view their own todos"
  ON public.todos
  FOR SELECT
  USING (auth.uid() = user_id);

-- 策略2：用户只能插入自己的 todos
CREATE POLICY "Users can insert their own todos"
  ON public.todos
  FOR INSERT
  WITH CHECK (auth.uid() = user_id);

-- 策略3：用户只能更新自己的 todos
CREATE POLICY "Users can update their own todos"
  ON public.todos
  FOR UPDATE
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

-- 策略4：用户只能删除自己的 todos
CREATE POLICY "Users can delete their own todos"
  ON public.todos
  FOR DELETE
  USING (auth.uid() = user_id);

-- ============================================
-- 6. 启用 Realtime 功能
-- ============================================
-- 为 todos 表启用 Realtime，支持实时订阅
ALTER PUBLICATION supabase_realtime ADD TABLE public.todos;

-- ============================================
-- 7. 创建 Storage bucket（用于图片存储）
-- ============================================
-- 注意：这个需要在 Supabase Dashboard 的 Storage 中手动创建
-- 或者使用以下 SQL（如果有权限）：

-- 插入 bucket 配置
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES (
  'my-todo',
  'my-todo',
  true,  -- 公开访问
  5242880,  -- 5MB 限制
  ARRAY['image/jpeg', 'image/jpg', 'image/png', 'image/gif', 'image/webp']
)
ON CONFLICT (id) DO NOTHING;

-- ============================================
-- 8. Storage RLS 策略（用于图片上传）
-- ============================================

-- 允许认证用户上传文件到自己的文件夹
CREATE POLICY "Users can upload images to their own folder"
  ON storage.objects
  FOR INSERT
  TO authenticated
  WITH CHECK (
    bucket_id = 'my-todo' AND
    (storage.foldername(name))[1] = auth.uid()::text
  );

-- 允许所有人查看图片（因为 bucket 是公开的）
CREATE POLICY "Anyone can view images"
  ON storage.objects
  FOR SELECT
  TO public
  USING (bucket_id = 'my-todo');

-- 允许用户删除自己文件夹中的图片
CREATE POLICY "Users can delete their own images"
  ON storage.objects
  FOR DELETE
  TO authenticated
  USING (
    bucket_id = 'my-todo' AND
    (storage.foldername(name))[1] = auth.uid()::text
  );

-- 允许用户更新自己文件夹中的图片
CREATE POLICY "Users can update their own images"
  ON storage.objects
  FOR UPDATE
  TO authenticated
  USING (
    bucket_id = 'my-todo' AND
    (storage.foldername(name))[1] = auth.uid()::text
  );
```
**数据表对应功能实现 prompt**

```
#file:page.tsx  请你结合 #file:init.sql  数据表，结合 supabase 完成真实的数据连接到数据库中，要求实现：
1. 当用户登录后，用登录态获取到当前用户的 todo数据。
2. 实现用户增加todo 并保存的功能。
3. 实现用户修改todo 并保存的功能。
4. 实现用户删除todo 并保存的功能。
5. 实现用户点击完成，修改完成 保存的功能
6. 确保 新增，修改，删除的都是当前用户的数据
```

> 输入上线 prompt 之后，ai 就会完成对应 增删该查的功能。

## supabase  文件上传

1. 首先需要在 supabase 的 storage 中创建一个 bucket （my-todo)
2. 然后对 my-todo 做一些权限管理
3. 点击 my-todo ，点击 policies。
4. 点击 new policy 

**上传 prompt**

```

我希望给该项目添加文件上传的功能：
1. 当前用户上传图片给当前增加的todo作为附件，只能上传一个附件。
2. 附件需要先上传到名为 my-todo 的bucket 下（已有该bucket），路径为当前用户的uid目录下，并返回附件的预览地址。
3. 附件的预览地址需要保存在数据库中，请你给 init.sql 中添加一个字段 image_url 。
```

# supabase  实时功能

当数据更新时，supabase 可以同步更新其他设备，或浏览器的数据渲染。

**实时功能实现 prompt**

```
#page   请你给这个应用添加 supabase 的实时功能：

1. 当用户更新自己的数据之后，init.sql 这张表的数据可以实时同步到其他设备中。
2. 确保用户的新增，修改，删除等操作都可以触发视图渲染的更新。
```
