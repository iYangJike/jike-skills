# 调研介绍技能

当用户想了解某个工具、技术、概念或任何不熟悉的东西时，按以下流程执行。

## 第一步：判断模式

- **默认**：使用**快速模式**（目标是 3 分钟内读懂）
- 用户说「深度」「详细」「全面」「deep」时，切换为**深度模式**（包含原理、生态、竞品）
- 用户说「快速」「简单」「fast」「大概」时，确认使用**快速模式**

## 第二步：多渠道调研

按以下优先级从多个来源获取信息，至少覆盖 3 个不同来源：

1. **官方文档/官网** — 用 `web_search` 搜 `[关键词] official documentation` 或 `[关键词] 官网`
2. **GitHub 仓库** — 如果是开源工具，搜 `[关键词] github`，用 `web_extract` 读 README
3. **技术文章/教程** — 搜 `[关键词] tutorial`、`[关键词] 入门`、`[关键词] 是什么`
4. **社区讨论** — 搜 `[关键词] review`、`[关键词] vs`、`[关键词] 优缺点`
5. **竞品对比** — 搜 `[关键词] alternatives`、`[关键词] vs [同类工具]`

对于链接或图片输入：直接用 `web_extract` 或 `vision_analyze` 分析内容，然后执行同样的结构化输出。

重要：调研时用 `web_search` 和 `web_extract` 并行获取多个来源，不要串行等待。

## 第三步：输出

### 快速模式输出模板

```
# [关键词] 是什么？

## 一句话概括
[一句话说清这个东西是什么、解决什么问题]

## 核心概念
- **概念 1**：[通俗解释]
- **概念 2**：[通俗解释]
- **概念 3**：[通俗解释]

## 典型使用场景
1. **场景 A**：[什么情况下用]
   例子：[具体实例]
2. **场景 B**：[什么情况下用]
   例子：[具体实例]
3. **场景 C**：[什么情况下用]
   例子：[具体实例]

## 快速上手
[3-5 步最小化操作，让用户能立刻试起来]
```

### 深度模式输出模板

在快速模式基础上，追加以下章节：

```
## 技术原理
[核心工作原理，文字描述架构/流程]

## 生态与竞品对比
| 工具 | 定位 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| [关键词] | ... | ... | ... | ... |
| [竞品A] | ... | ... | ... | ... |
| [竞品B] | ... | ... | ... | ... |

## 深入使用场景
[详细场景分析，包含边界条件、注意事项、最佳实践]

## 学习路径
1. 入门：[推荐资源]
2. 进阶：[推荐资源]
3. 深入：[推荐资源]

## 信息来源
- [来源1](url)
- [来源2](url)
- ...
```

## 注意事项

- 对于陌生领域的概念，多用类比和举例，避免堆砌术语
- 竞品对比要客观，不吹不黑，明确各自的适用场景
- 如果某个信息在调研来源中找不到，诚实说明，不要编造
- 快速上手步骤必须是可执行的，不能是「去官网看文档」这种废话
- 如果用户给的是链接或图片，先分析内容，再判断是否需要额外调研
